# Model Card

## Общая информация

**Название модели:**  
MBARTRuSumGazeta (`IlyaGusev/mbart_ru_sum_gazeta`)

**Источник:**  
[Страница модели на Hugging Face](https://huggingface.co/IlyaGusev/mbart_ru_sum_gazeta)

**Автор / организация:**  
Илья Гусев (Ilya Gusev)

**Задача модели:**  
Суммаризация новостных текстов. Модель создаёт краткий пересказ статьи. Это модель mBART, дообученная на датасете Gazeta.

**Язык:**  
Русский

**Лицензия:**  
Apache-2.0

## Использование в проекте

Модель выполняет основную функцию сервиса: создаёт краткий пересказ в сценарии UC-01
(см. [Требования](../project/requirements.md) и [Диаграммы](../project/diagrams.md)).

1. Пользователь отправляет текст через `POST /summaries`, запрос попадает в очередь задач.
2. Сервис забирает задачу из очереди и передаёт модели исходный текст.
3. Результат сохраняется как новая версия `Summary`, а в поле `modelVersion` записывается версия модели.
4. Клиент получает статус и пересказ через `GET /summaries/{id}`.

Если модель недоступна, запрос получает статус `ERROR`, а пользователь видит код
`MODEL_UNAVAILABLE` и подсказку, что делать дальше. Подробнее операции описаны в разделе [API](../api/index.md).

## Входные данные

Текст на русском языке. При обучении и оценке авторы обрезали вход до 600 токенов.
Технический предел модели составляет 1024 позиции (`max_position_embeddings` в `config.json`).

## Выходные данные

Текст краткого пересказа. При оценке авторы ограничивали его 200 токенами,
средняя длина результата на тесте Gazeta v1 составила 371 символ.

## Метрики качества

Значения указаны на странице модели. Обучение выполнено на Gazeta v1 train,
параметры оценки: вход 600 токенов, выход 200 токенов, `num_beams` 5, `no_repeat_ngram_size` 4.

| Тестовая выборка | ROUGE-1 | ROUGE-2 | ROUGE-L | chrF | METEOR | BLEU |
|:-----------------|:--------|:--------|:--------|:-----|:-------|:-----|
| Gazeta v1 test   | 32.4    | 14.3    | 28.0    | 39.7 | 26.4   | 12.1 |
| Gazeta v2 test   | 28.7    | 11.1    | 24.4    | 37.3 | 22.7   | 9.4  |

В статье авторов значения немного отличаются (например, ROUGE-1 равен 32.1).
Авторы отмечают, что эти метрики неидеальны: они считают совпадения с единственным эталонным пересказом.

В статье также приведено сравнение с участием людей: на 1000 примеров пересказ mBART выбрали
чаще эталонного в 735 случаях. Авторы предупреждают, что это не доказывает превосходство модели
над человеком, потому что разметчики не оценивали абстрактивность пересказов.

## Ограничения

### Указано авторами

- Модель должна хорошо работать со статьями Gazeta.ru, но на текстах других изданий качество может снижаться из-за domain shift.
- При обучении и оценке вход обрезался до 600 токенов, поэтому продолжение длинного текста модель не учитывала.
- Модель может ошибаться: в статье приведены пересказы с фактической ошибкой, повтором и несвязным предложением.

### Мой анализ

**Потенциальное ограничение для нашего проекта:**  
Модель получает на вход только текст, передать ей инструкции нельзя.
Поэтому US-03 и `POST /summaries/{id}/revisions` на этой модели не реализовать.
Для доработки пересказа по замечаниям нужна отдельная модель, которая умеет следовать инструкциям.

**Потенциальное ограничение для нашего проекта:**  
Сервис принимает любые тексты, а модель обучена только на новостях.
Качество на учебных, научных и деловых текстах не указано авторами модели, его нужно проверить отдельно.

## Не рекомендуется использовать

Не указано авторами модели.

По нашей оценке, модель не стоит использовать:

- для принятия медицинских, юридических и финансовых решений без чтения исходного текста;
- как источник проверенных фактов;
- для длинных документов без разбиения на части;
- для текстов не на русском языке.
