# User stories

### US-01. Пересказ вставленного текста

Как контент-менеджер, я хочу вставлять текст статьи в сервис, чтобы быстро получить краткий пересказ для анонса.

Критерии приемки:

- Сервис имеет поле ввода (копирования) текста
- По итогу работы сервис предоставляет краткий пересказ, с которым контент-менеджер может взаимодействовать (выделить, скопировать)
- В случае внутренней ошибки сервиса контент-менеджер должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-02. Пересказ текста из файлов

Как контент-менеджер, я хочу загружать файл(ы) с текстом в сервис, чтобы получать краткий пересказ материалов авторов без ручного копирования.

Критерии приемки:

- Сервис поддерживает отправку файлов с текстом в конкретных форматах (.txt, .md, .docx, .pdf)
- По итогу работы сервис предоставляет краткий пересказ, с которым контент-менеджер может взаимодействовать (выделить, скопировать)
- В случае невозможности обработки файлов или внутренней ошибки сервиса контент-менеджер должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-03. Доработка пересказа по замечаниям

Как контент-менеджер, я хочу указывать, что именно не так в кратком пересказе, чтобы получить вариант, подходящий для публикации.

Критерии приемки:

- Контент-менеджер может отправить пересказ на доработку и указать, что именно не так
- По итогу такой работы сервис создаёт новую версию пересказа и показывает её вместо предыдущей. С новой версией контент-менеджер может взаимодействовать (выделить, скопировать)
- Предыдущие версии не удаляются и остаются в системе
- Новую версию тоже можно отправить на доработку
- В случае внутренней ошибки сервиса контент-менеджер должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-04. Отслеживание статуса обработки

Как контент-менеджер, я хочу видеть актуальный статус обработки текста, чтобы понимать, готов ли пересказ и не произошла ли ошибка.

Критерии приемки:

- Все запросы по пересказу текста ложатся в очередь, откуда могут быть извлечены даже в случае неожиданного падения сервиса
- Контент-менеджер видит статус обработки переданного текста на странице сервиса


# Use cases

### UC-01. Автоматический краткий пересказ

Актор: контент-менеджер

Цель: получить качественный краткий пересказ статьи для анонса

Предусловие: контент-менеджер вставил нужный текст в текстовое поле

Основной сценарий:

1. Контент-менеджер отправляет текст.
2. Запрос на обработку ложится в очередь задач.
3. Сервис достает запрос из очереди, получает текст и принимается за пересказ, показывая статус обработки контент-менеджеру.
4. ML-модель производит суммаризацию полученного текста.
5. Система получает результат и сохраняет его как первую версию пересказа.
6. Контент-менеджер видит результат суммаризации.

Альтернативный сценарий:

Если пересказ не подходит, контент-менеджер отправляет его на доработку и указывает, что именно не так.
Сервис обрабатывает исходный текст заново с учётом этих инструкций и сохраняет результат как новую версию пересказа.
Контент-менеджер видит новую версию вместо предыдущей, а предыдущая версия остаётся в системе.

Результат: контент-менеджер получает краткий пересказ, учитывающий указанные замечания
