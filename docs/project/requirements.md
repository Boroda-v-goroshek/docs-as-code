# User stories

### US-01. Автоматический краткий пересказ

Как пользователь, я хочу уметь отдавать текст сервису, чтобы получить его краткий пересказ.

Критерии приемки:
- Сервис имеет поле ввода (копирования) текста
- По итогу работы сервис предоставляет его краткий пересказ, с которым пользователь может взаимодействоать (выделить, скопировать)
- В случае внутренней ошибки сервиса пользователь должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-02. Автоматический краткий пересказ

Как пользователь, я хочу уметь отдавать файл(ы) с текстом сервису, чтобы получить краткий пересказ содержимого.

Критерии приемки:
- Сервис поддерживает отправку файлов с текстом в конкретных форматах (.txt, .md, .docs, .pdf)
- По итогу работы сервис предоставляет его краткий пересказ, с которым пользователь может взаимодействоать (выделить, скопировать)
- В случае невозможности обработки файлов или внутренней ошибки сервиса пользователь должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-03. Автоматический краткий пересказ

Как пользователь, я хочу уметь поправлять работу сервиса, указывая что именно не так в кратком пересказе, чтобы получить более качественный краткий пересказ.

Критерии приемки:
- У пользователя должна быть возможность сказать сервису переделать пересказ, с указанием конкретных причин или инструкций
- По итогу такой работы сервис предоставляет новый краткий пересказ (взамен старого), с которым пользователь может взаимодействоать (выделить, скопировать)
- Должна быть возможность переделать новый пересказ
- В случае внутренней ошибки сервиса пользователь должен получать информацию об ошибке и короткое объяснение, что делать дальше

### US-04. Автоматический краткий пересказ

Как пользователь, я хочу видеть актуальный статус обработки текста, чтобы быть в курсе происходяшего.

Критерии приемки:
- Все запросы по пересказу текста ложатся в очередь, откуда могут быть извлечены даже в случае неожиданного падения сервиса
- Пользователь видит статус обработки переданного текста на странице сервиса


# Use cases

### UC-01. Автоматический краткий пересказ

Актор: пользователь

Цель: получить качественный краткий пересказ переданного текста

Предусловие: пользователь вставил нужный текст в текстовое поле

Основной сценарий:

1. Пользователь отправляет текст.
2. Запрос на обработку ложится в очередь задач.
3. Сервис достает запрос из очереди, получает текст и принимается за пересказ, показывая статус обработки пользователю.
4. ML-модель производит суммаризацию полученного текста.
4. Система получает результат.
5. Пользователь видит результат суммаризации.

Альтернативный сценарий:

Если пользователя не устраивает полученный пересказ, он сообщает об этом сервису и
описывает моменты, которые кажутся ему ошибочными. Сервис принимает переданные инструкции и обрабатывает текст заново, учитывая переданные инструкции.


Результат: пользователь получает краткий пересказ, учитывающий его требования
